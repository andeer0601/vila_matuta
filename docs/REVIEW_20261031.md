# Revisão do Vila Matuta — 31/10/2026

## Resultado

Aplicação preparada para uma demonstração pública **isolada, exclusivamente fictícia**. Nenhum deploy foi feito. A publicação ainda depende de configurar um host Next.js/Node com HTTPS e executar o roteiro de aceite no domínio final. Não usar essa demonstração para vendas ou dados pessoais reais.

## Correções realizadas

- Entrada com três perfis sem senha: Mariana, Lucas e Anderson (Administrador). Escolha de visão pela tela `/entrar`; início sem usuário, troca de perfil e saída explícitas. Referências a “dono” removidas da interface.
- Avisos claros de simulação, ausência de autenticação real, dados locais e ausência de cobrança/entrega/mensagens. Telefones/CEP fictícios e e-mails `example.invalid` nos fixtures.
- Public demo opt-in em build de produção, bloqueio de todas as APIs por middleware e defesa adicional nas funções de banco, Supabase browser e InfinitePay. Build/check-env recusam configuração de demo com credenciais reais ou pagamentos ativos; variáveis públicas inesperadas preenchidas também são recusadas.
- ViaCEP simulado localmente. Atendimento demo não abre WhatsApp. Recuperação de senha demo orienta voltar à escolha de perfil sem pedir senha.
- Namespace `vm_public_demo_v1_` separa os testes novos dos dados anteriores. Reset pede confirmação e remove somente esse prefixo; cancelamento preserva dados. Sair mantém o cenário para retomada.
- Webhook real retorna 429 com Retry-After e 5xx em falhas transitórias de consulta/confirmação, em vez de transformar tudo em erro 400.
- Criação e agendamento local protegidos com Web Locks para reduzir conflitos entre abas. As regras comerciais e preços existentes foram preservados.
- Laranja principal branco/texto: contraste de 3,56:1 para 5,15:1. Bordas de campos mais definidas, textos pequenos ampliados, inputs móveis de 16px, foco visível, link de pular conteúdo e respeito a movimento reduzido.
- Navbar responsiva; cabeçalho não ocupa a área de leitura enquanto se rola no celular. Formulários e botões reorganizados para larguras pequenas.
- Rótulos acessíveis, seleções com aria-pressed, progressos nomeados, hierarquia de títulos, ID duplicado removido e landmark main único na tela de endereços.
- Cidade e UF podem ser editadas; consulta concorrente de CEP não sobrescreve a resposta mais nova. Endereço específico e preferência do cadastro mantêm seus contextos.
- Quantidade escolhida no simulador da home prevalece ao abrir o montador, preservando o restante do rascunho. Aviso quando total escolhido excede a meta.
- Estados de erro e página 404 com recuperação. Textos que prometiam WhatsApp/Pix automático foram corrigidos. Impressão não inclui botões/cabeçalho/rodapé e libera conteúdo rolável.

## Evidência automatizada

- **45 testes Node aprovados**, incluindo testes PostgreSQL via PGlite: capacidade, propriedade, RLS/grants, pagamentos idempotentes, saldo por sabor, reservas/expiração, remarcação, endereços, criptografia/tampering/rotação, validação e IDOR.
- Novos testes: matriz de modo demo/produção; todas as famílias de APIs bloqueadas antes dos handlers; banco e gateway bloqueados por chamada direta; CEP sem fetch; webhook preserva 429/Retry-After e falhas 500; reset conserva dados fora do namespace.
- Build Next.js de produção com demo explícita e validação TypeScript aprovados. Executado com Node 22.22.1 e pnpm 11.19.0 via Corepack.
- Smoke HTTP em servidor de produção local: **51 chamadas (GET/POST/HEAD em 17 caminhos) retornaram 403**, incluindo /api e sufixos png/jpg/jpeg/webp/svg/ico, página de entrada 200 e página inexistente 404. CSP sem unsafe-eval, frame protection, nosniff, referrer-policy, permissions-policy, no-store e noindex verificados.
- Auditoria remota de dependências de produção: inicialmente 1 crítico + 1 alto no Next.js 15.5.27. Atualizado para **15.5.28**, package.json e pnpm-lock.yaml atualizados. Auditoria posterior: **No known vulnerabilities found**.
- Avisos consultados: [GHSA-2464-fhr4-w9xw](https://github.com/advisories/GHSA-2464-fhr4-w9xw), [GHSA-p3m5-59mp-jv5r](https://github.com/advisories/GHSA-p3m5-59mp-jv5r). O primeiro tem condições específicas de plataforma/imagens e o segundo envolve Server Actions; atualizar elimina os avisos do inventário, sem afirmar exploração comprovada neste projeto.

## Limites e pendências

- Sem Git nesta pasta: `git status` retorna “not a git repository”. Não houve commit/push ou comparação com uma base versionada. Nenhum arquivo preexistente do projeto foi removido.
- Demo é pública por definição e dados locais podem ser vistos/alterados por quem usa o mesmo navegador; controles de UI não são autenticação. Orientação de usar somente dados inventados é essencial.
- Configuração do host, domínio, HTTPS/HSTS efetivo, WAF/cotas, headers de proxy, logs e consumo precisam de validação no destino. Não houve deploy.
- Integrações reais (Supabase, SMTP/CAPTCHA, InfinitePay), migrações em conta externa e pagamento real não foram executados. Testes SQL usaram PGlite local.
- Para vender: definir frete/área atendida, homologar pagamento/retorno/webhook e reentrega, cancelamento/reembolso, privacidade/retenção/exclusão/exportação e MFA administrativo. Não confundir os testes demo com aceite dessas funções reais.
- Navegação cobre os fluxos principais e os casos descritos; não é garantia de ausência de bugs, teste de carga, pentest externo ou revisão exaustiva de todas as combinações possíveis.

Instruções de host e aceite: [PUBLIC_DEMO.md](PUBLIC_DEMO.md). As afirmações anteriores de que demo só executa em desenvolvimento foram substituídas nesta revisão.

## Endurecimento após revisão independente final

Validadores unificados em scripts/demo-environment.cjs, compartilhado por next.config.mjs e check-env. Ambos recusam credenciais, segredos de criptografia/rate limit, variáveis públicas inesperadas e PAYMENTS_ENABLED ausente ou diferente de false. Testes invocam os dois pontos de entrada reais em nove configurações e exigem os mesmos resultados.

Middleware agora aplica CSP, nosniff, DENY, referrer-policy, permissions-policy e no-store também ao 403 antecipado; HSTS é coberto em requisição HTTPS unitária. Na demo de produção connect-src fica limitado a self e frame-src a none, sem ViaCEP, Supabase ou Cloudflare. Matcher explícito /api/:path* cobre APIs com sufixos de imagem.

Script reproduzível scripts/test-demo-http.cjs (pnpm test:demo-http) executado contra next start: 51 recusas 403 com headers completos, caminhos de API com sufixos de imagem bloqueados, página de login 200 e imagem WebP pública legítima 200. Build/TypeScript e 45 testes aprovados. Login fictício de Lucas e montador revalidados no navegador sob a CSP final, console sem erros/avisos. Nenhum deploy.
